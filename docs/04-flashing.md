# Прошивка и восстановление

> ⚠️ Прошивка из этого репозитория **не проверялась на живом устройстве**.
> Считайте её экспериментальной. Порядок ниже построен так, чтобы на каждом шаге
> оставалась дорога назад.

## Золотые правила

1. **Не трогать разделы `uboot`, `ubootconfigA/B`, `calibration`, `gphyfirmware`.**
   Пока цел `uboot` — роутер восстанавливается по TFTP. Пока цела `calibration` —
   у Wi-Fi есть калибровка и заводские MAC-адреса. Убьёте их — восстановить
   можно только программатором и чужим дампом (а калибровка у каждого экземпляра своя).
2. **Сначала бэкап, потом эксперименты.**
3. **Сначала загрузка в RAM, потом запись в NAND.**

## Шаг 0. UART

Понадобится обязательно: без консоли восстановление невозможно.

- Уровни **3.3 В**, скорость **115200 8N1**, аппаратный контроль потока выключен.
- Землю подключать первой; VCC с переходника **не подключать**.
- Разъём на плате AX50 — четырёхконтактный (GND / TX / RX / VCC). Точную распиновку
  определите тестером: GND звонится на экран разъёмов, TX выдаёт лог при включении.

Загрузчик даёт несколько секунд на прерывание автозагрузки — жмите Enter/любую клавишу
сразу после подачи питания.

## Шаг 1. Бэкап

С работающей стоковой прошивкой root-доступа нет, поэтому дамп снимаем **из U-Boot**:
поднимаем TFTP-сервер и по очереди выгружаем разделы (`nand read` в память → `tftpput`),
либо, если есть root (см. ниже про CVE), скриптом:

```bash
./scripts/backup-router.sh root@192.168.0.1
```

Минимально необходимый набор: `uboot`, `ubootconfigA`, `ubootconfigB`,
`gphyfirmware`, `calibration`, и целиком `system_sw`.

Полезно: на родственных TP-Link (Archer AX10/AX1500 до июля 2022) root получают через
**CVE-2022-30075** — см. [Waujito/TPLlAX1500GPL](https://github.com/Waujito/TPLlAX1500GPL).
На AX50 со свежей прошивкой это закрыто; проверять на свой страх и риск.

## Шаг 2. Проверка без записи — загрузка в RAM

Самый безопасный тест: ничего не пишем в NAND, грузим ядро в память.

Для этого собирается отдельный образ **`TPLINK_AX50-initramfs-kernel.bin`** —
ядро с rootfs внутри, работающее целиком в оперативной памяти.

```
# на ПК: статический IP 192.168.1.2/24, TFTP-сервер с образом в корне
# в консоли U-Boot:
setenv ipaddr 192.168.1.1
setenv serverip 192.168.1.2
tftpboot 0x82000000 TPLINK_AX50-initramfs-kernel.bin
bootm 0x82000000
```

Если система не поднялась — просто перезагрузите роутер, стоковая прошивка на месте.
На этом шаге проверяются: старт ядра, консоль, Ethernet, загрузка модулей.
Что смотреть в первую очередь:

```sh
dmesg | head -50                 # старт ядра, определилась ли плата
cat /tmp/sysinfo/board_name      # должно быть tplink,archer-ax50-v1
cat /proc/mtd                    # разметка NAND — сверить с docs/01-hardware.md
cat /proc/meminfo                # реальный объём ОЗУ
ip link                          # интерфейсы eth0_1..eth0_4, eth1
lsmod | grep -E 'mtlk|cfg80211'  # Wi-Fi-драйвер загрузился
dmesg | grep -i -E 'mtlk|wav|wlan'
```

## Шаг 3. Запись в NAND

Процедура унаследована от родственной платы Netgear RAX40 на том же GRX350
(см. [wiki prplOS](https://gitlab.com/prpl-foundation/prplos/prplos/-/wikis/RAX-40-flashing-via-bootloader)).
Команды U-Boot Intel/Lantiq:

```
setenv fullimage TPLINK_AX50-squashfs-fullimage.img
saveenv
run update_fullimage
reset
```

Если `update_fullimage` не проходит из-за размера, можно освободить второй банк
и обновлять только банк A:

```
run ubi_init
ubi remove rootfsB
ubi remove kernelB
setenv update_owrt 'run ubi_init;tftpboot $(loadaddr) $(tftppath)$(fullimage);run switchbankA;set update_chk 0;upgrade $(loadaddr) $(filesize)'
saveenv
run update_owrt
```

> Набор команд в U-Boot AX50 нужно **сверить с реальным устройством**: наберите
> `printenv` и посмотрите, какие макросы (`update_fullimage`, `ubi_init`,
> `switchbankA`, `upgrade`) там есть. Если имена другие — не импровизируйте,
> сначала выпишите окружение целиком в бэкап.

## Шаг 4. Обновления после установки

Когда prplWrt уже работает:

```bash
sysupgrade -v TPLINK_AX50-squashfs-sysupgrade.bin
```

## Возврат на стоковую прошивку

1. Скачайте официальный образ с
   [страницы поддержки AX50 V1](https://www.tp-link.com/us/support/download/archer-ax50/v1/).
2. Из U-Boot залейте его тем же способом, что и наш `fullimage` — формат TP-Link
   Totalimage содержит U-Boot, GPHY FW, rootfs и ядро, то есть восстанавливает систему целиком.
3. Если сохраняли собственный дамп `system_sw` — можно вернуть именно его.

## Если роутер не стартует

- Есть консоль → всё поправимо: TFTP-восстановление по шагу 3.
- Консоли нет и загрузчик молчит → повреждён `uboot`; нужен SPI/NAND-программатор
  и заранее снятый дамп. Это ровно та причина, по которой шаг 1 не пропускают.
